# MACD Alert Bot на GitHub Actions

Скрипт по cron проверяет MACD по ЗАКРЫТЫМ свечам и шлёт email при смене цвета гистограммы:
- светлозелёная (выше 0, падает) -> тёмно-зелёная (растёт) = СИГНАЛ GREEN
- светло-красная (ниже 0, растёт) -> тёмно-красная (падает) = СИГНАЛ RED

Всё настраивается и управляется со СМАРТФОНА.

## Установка (только телефон, ~15 минут)

1. **Заведите аккаунт GitHub** — через браузер на телефоне (github.com → Sign up).
2. **Создайте репозиторий** — кнопка «+» → New repository → имя `macd-alert`
   → **Public** (у публичных репозиториев GitHub Actions бесплатный без лимита минут;
   приватные дают 2000 мин/мес — тоже хватит для ТФ от 1h).
3. **Загрузите файлы** — в репозитории: Add file → Create new file → в поле имени
   введите `macd_alert.py`, вставьте содержимое из этого архива. Повторите для
   `config.json` и `.github/workflows/macd-alert.yml` (создавайте папки прямо
   в имени файла через `/`). Либо Add file → Upload files — можно загрузить
   файлы из памяти телефона.
4. **Добавьте секреты** — Settings → Secrets and variables → Actions →
   New repository secret. Создайте три секрета:
   - `EMAIL_TO` — куда слать уведомления
   - `EMAIL_USER` — ваш Gmail-адрес (с него отправка)
   - `EMAIL_APP_PASSWORD` — пароль приложения Gmail: myaccount.google.com →
     Безопасность → Пароли приложений → создать (нужен обычный пароль аккаунта
     для входа в настройки). Это НЕ обычный пароль почты.
5. **Настройте config.json** — вкладка с файлом → значок карандаша:
   `ticker` (BTC-USD, ETH-USD, AAPL...), `timeframe` (1h, 4h, 1d...), параметры MACD.
6. **Включите Actions** — вкладка Actions → «I understand my workflows, go ahead».
7. **Тест** — Actions → MACD Alert → Run workflow → Run. Через ~1 минуту
   зайдите в запуск и раскройте шаг «Проверка MACD...» — там лог: цвет гистограммы
   и был ли сигнал. Если был — проверьте почту.

## Как изменить расписание (таймфрейм)

Расписание — строка cron в `.github/workflows/macd-alert.yml` (редактируется
с телефона: файл → карандаш). cron работает по UTC. Готовые варианты:

| ТФ | Строка cron |
|----|-------------|
| 15m | `'2,17,32,47 * * * *'` |
| 30m | `'2,32 * * * *'` |
| 1h | `'2 * * * *'` |
| 4h | `'2 0,4,8,12,16,20 * * *'` |
| 1d | `'7 0 * * *'` (00:07 UTC) |

Изменили ТФ в config.json — поменяйте и cron, иначе проверки будут идти не вовремя.

## Важные нюансы

- **Проверки только после закрытия свечи** (cron в :02, а не в :00) — без перерисовки.
- **Дедупликация**: state.json хранится в репозитории, повторных писем по той же
  свече не будет.
- **Задержки GitHub**: cron-запуски могут опаздывать на 1–10 минут при нагрузке.
  Для трейдинг-сигнала это некритично, но знайте.
- **Автоотключение**: GitHub выключает cron у репозитория без активности 60 дней.
  Лечится: зайти в Actions и нажать Run workflow, либо любой коммит. При
  регулярных сигналах state.json сам держит репозиторий «живым».
- **ТФ короче 15м** (5м, 1м) — технически возможно, но тысячи запусков в месяц
  могут упираться в лимиты приватного репозитория; используйте 15м и выше.
- **Логи каждой проверки** видны во вкладке Actions — можно с телефона смотреть,
  какой сейчас цвет гистограммы, даже когда сигнала нет.
